# Kibborg — правила для агентов

## Паритет Telegram ↔ Web (обязательно)

**Всё, что добавляется для Telegram-агента, должно добавляться и для веб-версии — и наоборот.**

Интерфейсы разные (чат Telegram vs локальная панель `http://127.0.0.1:PORT_WEB`), но **возможности и инструменты** должны совпадать:

| Возможность | Telegram | Web |
|---|---|---|
| Чат с LLM | текст / голос | `/api/chat` (+ 🎙 mic в Web) |
| STT (речь→текст) | Telegram voice/audio | mic / audio upload → TypeWhisper API, fallback whisper.cpp |
| Картинки / vision | photo / document | multipart upload |
| `/chart` разбор графика | команда + скрин | картинка + `/chart` в подписи или сообщении |
| `/analyze` тикер | команда | вкладка Анализ + API |
| `/browser` Browser Agent | команда | вкладка Браузер + `/api/browser` + `/browser` в чате |
| `/download` видео (YouTube/Instagram/…) | команда или голая ссылка | вкладка Видео + `/api/download_video` + ссылка в чате |
| Разбор видео (речь→текст, кадры→описание) | video / video_note / animation / документ | upload в чат (стримится на диск) |
| Разбор PDF (текстовый слой или распознавание скана) | документ .pdf | upload в чат |
| `/reset` | команда | кнопка Сброс |
| Артефакты (скрин/видео/файлы) | sendPhoto / sendVideo / путь | ссылки `/api/files/…` |
| Остановить задачу | `/stop` (до очереди) | кнопка ⏹ Стоп + `/api/stop` |
| Режим рук safe/full | `/hands` (до очереди) | тумблер в шапке + `/api/hands` |
| Подтверждение опасного шага | ответ «да» / «нет» | кнопки ✅/🚫 + `/api/confirm` |

### Как соблюдать при новой фиче

1. Реализуй **общее ядро** (пакет `browser`, `trading`, общий helper) — без привязки к каналу.
2. Подключи **Telegram** (`main.go` / команды / `sendArtifacts`).
3. Подключи **Web** (`webui.go` API + `web/index.html` UI).
4. Обнови help (`/start`) и подсказки в UI.
5. Добавь/обнови тесты на обе стороны, если меняется контракт.

Не делай «только в Telegram, веб потом» и не делай «только кнопку на вебе без команды в боте».

## Слойный агент

Любой запрос — текстом, голосом, слэшем или картинкой — идёт по одной трубе:

```
вход → [Task: taskID, Actor, ctx с TaskTimeout 10 мин]
     → СЛОЙ 1 диспетчер (тулов нет) → JSON {packs, plan, confirm, summary}
     → СЛОЙ 2 сбор рук (схемы паков + always-on request_pack)
     → СЛОЙ 3 исполнение: tool_call → guardToolCall → allow / ask / deny / hard_block
     → СЛОЙ 4 ответ: summary первой строкой, plan лентой статусов
```

Ключевые файлы: `dispatcher.go` (слой 1), `packs.go` (слой 2), `agent_loop.go` (слои 3–4),
`guard.go` (ворота), `task.go` (задача + реестр + журналы), `pending.go` (подтверждения),
`handsmode.go` (рубильник), `tools_local.go` (паки `trade` / `secops`),
`system_tools.go` + `desktop_windows.go` (пак `system` — рабочий стол),
`video.go` + `video_tools.go` + `video_ingest.go` (слой видео),
`compact.go` (сжатие контекста), `telegram_menu.go` (кнопка команд и инлайн-панель).

### Паки инструментов

| Пак | Состав |
|---|---|
| `chat` | только `request_pack` |
| `web` | `web_search`, `semantic_search`, `read_url`, `http_get`, `github_search`, `youtube_transcript`, `agent_reach*` |
| `browser.read` | вкладки, `open_url`, текст/DOM/extract/сеть, скрин |
| `browser.act` | клик, ввод, скролл, формы, upload, drag, `close_page` |
| `console` | `run_command` |
| `files` | `read_file`, `write_file`, `list_dir`, `file_info`, `mkdir`, `delete_path`, `read_document` |
| `system` | `capture_screen`, `list_windows`, `focus_window`, `type_keyboard`, `press_keys`, `mouse_action`, `list_processes`, `kill_process`, `launch_app`, `clipboard` |
| `media` | `download_video`, `youtube_transcript`, `analyze_video`, `transcribe_media`, `video_frames`, `media_info`, `convert_media` |
| `trade` | `analyze_ticker`, `size_position`, `journal_add`, `journal_stats` |
| `secops` | `analyze_log`, `scan_text`, `audit_file` |

Новый tool → схема в нужный пак (`browser/tools.go`, `tools_local.go` или `system_tools.go`) +
ветка в `Dispatch` (или `dispatchLocalTool`) + при необходимости правило в `guard.go`.
**`TestPackSchemaBudget` (12 000 символов до ×3) — жёсткий: режь описания схем, не порог.**
Диспетчер выдаёт максимум `maxInitialPacks` = 3 пака; тест перебирает ВСЕ тройки, потому что
союз всех паков сразу недостижим, а вот любая тройка — вполне.

`system` — это ПК за пределами браузера. `capture_screen` снимает настоящий экран Windows;
`capture_screenshot` из `browser.read` — только вкладку Chrome. Путать их нельзя: именно на
этом агент отвечал пользователю «скриншот рабочего стола мне недоступен, нажмите Win+Shift+S».

**Глаза.** Сам снимок модель не видит — ей возвращается путь к файлу. `capture_screen(look="…")`
прогоняет снимок через зрение и отдаёт описание плюс координаты элемента для `mouse_action`;
пересчёт нормированной сетки в пиксели экрана делает Go, не модель. Зрение вызывается ОТДЕЛЬНЫМ
запросом без инструментов — §7 запрещает мешать `image_url` со схемами в одном запросе.

**Клики в браузере — по надписи.** `click_element` принимает `text=` (что видит человек) или
`selector=`. Поиск по тексту делает JS в странице, а нажатие — настоящее
`Input.dispatchMouseEvent`: синтетический `el.click()` живые приложения (Telegram Web) не
замечают, и клик «выполняется» вникуда. `get_html` на большом SPA бесполезен — обрезается и
уходит в таймаут; для поиска ориентиров есть `get_text`.

**Видео — это контейнер, а не модальность.** Своей «модели для видео» нет: ffmpeg режет ролик
на то, что движок уже умеет глотать — речь уходит в STT (`voice.go`), кадры в зрение
(`images.go`), метаданные читает ffprobe. Поэтому длина ролика упирается в диск, а не в окно
контекста: речь режется на куски по 5 минут, а модель получает ВЫЖИМКУ, полная расшифровка
ложится файлом (`read_file`, если нужны точные формулировки).

Приоритет источников текста: субтитры хостинга → субтитры внутри файла → распознавание. Для
ссылки без кадров качается только звук (`FetchMedia(audioOnly)`) — у часового доклада это
разница между 30 МБ и гигабайтом. Артефакты слоя лежат в `runtime/browser/media`: `/api/files`
отдаёт веб-панели ТОЛЬКО корень `runtime/browser`, и файл мимо него остаётся без ссылки.

Присланный в чат ролик разбирается ДО диспетчера и превращается в текст — ровно как картинка
(§4). Поэтому «разбери видео и найди проект на гитхабе» работает само: к моменту выбора
инструментов задача уже текстовая. Telegram отдаёт ботам только 20 МБ — это их лимит, и на
него отвечают не отказом, а двумя рабочими путями (ссылка или путь к файлу на диске).

**PDF — контейнер, а не модальность** (`document.go`, пак `files`). Порядок жёсткий: текстовый
слой (`pdftotext`, точно и бесплатно) → распознавание скана (`pdftoppm` 300 dpi → `tesseract`,
буквальные символы) → зрение только там, где tesseract вернул пустоту. Зрение для документа
последнее не случайно: модель «улучшает» текст, а для акта или договора это порча. Страница
считается картинкой, если текстового слоя в ней меньше `pdfPageTextMin` — сканы часто несут
тонкий слой из колонтитула. `read_file` на .pdf отказывает и называет `read_document`: файл
читается, но внутри сжатые потоки, и модель пересказывала мусор как содержание.

**Язык OCR обязан быть виден в отчёте.** Без `rus.traineddata` tesseract не падает — он выдаёт
правдоподобную латиницу («AKT npnéma-nepezaun»), и заметить подмену может только человек.
Поэтому языки печатаются в разборе, а их отсутствие — отдельным предупреждением.

**Нет опоры — переспроси** (`referent.go`, слой 0 перед диспетчером). «Найди мне ЭТОТ проект»
в пустом чате указывает на предмет, которого в разговоре нет; агент вместо вопроса «какой?»
выдавал подборку похожего — ответ на другой вопрос за шесть шагов. Проверка
детерминированная и молчит везде, кроме доказуемого случая: предмет не назван в самом
сообщении (нет ссылки, пути, кавычек, латиницы, разбора вложения) И в чате нет ни истории,
ни сумки ссылок. «Этот компьютер», «этот бот», «этот экран» — опора и так вокруг, вопрос не
задаётся. Ложное срабатывание тут дороже пропуска: агент, который переспрашивает вместо
работы, — то самое поведение, которое из движка выкорчёвывали (`armouryNote`).

**Провалившееся ДЕЙСТВИЕ приписывается к ответу кодом** (`Task.FailedActions`, `actionTools`):
модель умеет не заметить `failed` в результате инструмента и отчитаться об успехе. Факт из
журнала спорить не даёт. Провалившиеся чтения туда не попадают — это лишний шум.

### Безопасность

- Ворота стоят на **фактическом tool-call** (`guardToolCall`), а не на маршрутизации:
  диспетчер — удобство, не граница безопасности.
- `Decision{Action, Risk, Rule, Reason}`; `deny` («в этом режиме нельзя») и `hard_block`
  («нельзя никогда») — разные вещи, не смешивать.
- **Недостижимых действий нет.** Длина рук решает, спросят или нет:
  `safe` — рискованное спрашивает, ядерное отказывает; `full` — рискованное молча, ядерное
  спрашивает ОДИН раз. Ядерное = format/diskpart/bcdedit, снос корня диска, выключение ПК,
  убийство системных процессов. Деньги (`transfer`/`withdraw`/`place_order`/`cancel_order`)
  спрашивают в обоих режимах.
- Рубильник рук виден не только воротам, но и **промпту**: `armouryNote(packs, mode)` и
  блок про рабочие каталоги зависят от режима. Пока это было не так, развязанные руки не
  меняли того, что модель о себе думает, и она пересказывала пользователю свои ограничения.
- Режим рук — только runtime-store (`runtime/hands_mode.json`), никогда `settings.ini`.
- Полный терминал/файлы только при `TELEGRAM_ID` (Telegram) или localhost Web.
- Новые `/api/*` — обязательно через `sameOriginGuard`.
- В контекст модели уходит только `Status` + `Text` инструмента; файлы — человеку.

**Agent Reach** (опционально): `pip install agent-reach` → `agent_reach_doctor` / `run_command` с upstream CLI (twitter, gh, mcporter, bili…).
Встроенные без Python: `web_search`, `read_url` (Jina), `semantic_search` (Exa→DDG), `youtube_transcript`.

## Сборка и линтер (обязательно)

Сборка **только** через `engine-go/build.cmd` (или Menu → 4 / автосборка в `Start.cmd`):

1. `gofmt -l .` — неформатированный код = fail  
2. `go vet ./...`  
3. `staticcheck ./...` (ставится автоматически, если нет)  
4. `go build -buildvcs=false -o kibborg-go-engine.exe .`

Голый `go build` без линта — только для разовой отладки; в пайплайн запуска/меню так делать нельзя.  
Перед коммитом: `build.cmd` + `go test ./...`.
